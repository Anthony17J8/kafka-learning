# Этап 3 — Consumers

**Цель:** контролировать чтение, оффсеты и поведение группы при ребалансировке.

## Теория

- [Docs: Consumer configs](https://kafka.apache.org/documentation/#consumerconfigs)
- «Kafka: The Definitive Guide», гл. 4
- **KIP-848** — новый протокол ребалансировки, GA в Kafka 4.0.
  Ключевое отличие: координация переехала на сервер, ушли «stop-the-world» паузы.
- KIP-429 — incremental cooperative rebalancing (предшественник)

## Код в этой папке

| Класс | Что делает |
|---|---|
| `ManualCommitConsumer` | ✅ рабочий: ручной коммит + rebalance listener + graceful shutdown |
| `SeekingConsumer` | ✅ рабочий: `assign` + `offsetsForTimes` + `seek` |
| `LagMonitor` | ✅ рабочий: расчёт lag через AdminClient |

## Задачи

- [ ] 1. Запустить `ManualCommitConsumer`, разобрать вывод.
- [ ] 2. Запустить 2, 3, 4 инстанса на топике с 3 партициями.
      Зафиксировать в `NOTES.md`, что происходит с распределением и почему
      четвёртый инстанс простаивает.
- [ ] 3. Убить один инстанс во время работы — поймать в логах REVOKED/ASSIGNED.
- [ ] 4. Включить `group.protocol=consumer` (KIP-848), повторить эксперимент,
      **замерить время ребалансировки** в обоих режимах и сравнить.
- [ ] 5. Запустить `SeekingConsumer`, перечитать данные за последний час.
- [ ] 6. Запустить `LagMonitor`, сверить с `kafka-consumer-groups.sh --describe`.
      Дописать цикл с интервалом, чтобы видеть динамику lag.
- [ ] 7. Добавить `Thread.sleep` в `process()`, превысить `max.poll.interval.ms`,
      увидеть выброс из группы. Объяснить механизм.
- [ ] 8. Сравнить auto-commit и manual-commit: смоделировать падение
      сразу после poll и посмотреть, теряются ли сообщения.

## Контрольные вопросы

1. В чём разница между `session.timeout.ms` и `max.poll.interval.ms`?
   Какой из них ловит «зависшую обработку», а какой — «умерший процесс»?
2. Почему коммитим `offset + 1`, а не `offset`?
3. `onPartitionsRevoked` vs `onPartitionsLost` — почему во втором нельзя коммитить?
4. Как получить at-most-once, at-least-once и (почти) exactly-once
   только за счёт порядка «обработка ↔ коммит»?
5. Что произойдёт, если два консьюмера в разных группах читают один топик?
   А в одной группе с `assign` вместо `subscribe`?

## Результат этапа

Замеры времени ребалансировки для обоих протоколов, работающий монитор lag,
выводы по семантике коммитов.
