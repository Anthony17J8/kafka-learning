# Этап 1 — Фундамент и архитектура

**Цель:** понять модель данных Kafka как «распределённый append-only лог», а не как очередь.

## Теория

- [Docs: Design](https://kafka.apache.org/documentation/#design) — устройство лога, репликация, гарантии
- [Docs: Topic configs](https://kafka.apache.org/documentation/#topicconfigs) — retention, compaction, segments
- «Kafka: The Definitive Guide», гл. 1–2
- «DDIA», гл. 11 — почему лог оказался удачной абстракцией

Ключевые понятия: топик, партиция, оффсет, сегмент, реплика, лидер/фолловер,
ISR, high-watermark, retention, log compaction.

## Задачи (CLI, без Java)

- [ ] 1. Создать топик с 3 партициями и RF=3, изучить распределение реплик через `--describe`.
- [ ] 2. Отправить сообщения с ключами и без — сравнить распределение по партициям.
- [ ] 3. Прочитать с `--from-beginning`, затем с конкретной партиции и оффсета.
- [ ] 4. **Эксперимент с отказом:** остановить брокер-лидер, увидеть переизбрание,
      вернуть брокер, дождаться восстановления ISR.
- [ ] 5. Настроить `retention.ms=60000` на тестовом топике, дождаться удаления сегментов,
      подтвердить через `kafka-log-dirs.sh` или `--describe`.
- [ ] 6. **Log compaction:** создать топик с `cleanup.policy=compact`, записать несколько
      значений по одному ключу, дождаться компакции, убедиться что осталось последнее.
- [ ] 7. Изучить внутренние топики: `__consumer_offsets`, `__cluster_metadata`.

Все команды складывайте в `cli/` как исполняемые `.sh` файлы — это тоже артефакт.

## Контрольные вопросы

1. Почему число партиций легко увеличить, но нельзя уменьшить?
   Что ломается для ключей при увеличении?
2. В чём разница между `retention` и `compaction`? Можно ли включить оба сразу?
3. Что такое high-watermark и почему консьюмер не видит записи выше него?
4. При RF=3 и `min.insync.replicas=2`: что произойдёт с записью `acks=all`,
   если упадут два брокера из трёх?
5. Зачем нужен tombstone (запись с `null` значением) в compacted-топике?
