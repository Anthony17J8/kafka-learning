# Capstone — финальный проект

**Real-time система заказов и аналитики.** Собирает воедино всё, что изучено.

## Требования

### 1. Ingestion
Сервис заказов пишет в Postgres + outbox в одной транзакции.
Debezium публикует события (`OrderCreated`, `OrderPaid`, `OrderShipped`)
в Kafka в формате Avro с регистрацией схем в Schema Registry.

### 2. Обработка
Kafka Streams-приложение:
- обогащает заказы данными пользователей (stream-table join);
- считает оконные агрегаты (выручка за минуту/час, топ товаров);
- работает с `processing.guarantee=exactly_once_v2`;
- отдаёт текущее состояние через Interactive Queries.

### 3. Sink
Kafka Connect выгружает агрегаты в витрину для дашборда
и сырые события в объектное хранилище для архива.

### 4. Надёжность
RF=3, `min.insync.replicas=2`, `acks=all`, идемпотентные/транзакционные продюсеры,
идемпотентные консьюмеры.

### 5. Наблюдаемость
JMX → Prometheus → Grafana. Дашборд с техническими (lag, throughput, URP)
и бизнес-метриками (заказов/мин, выручка). Алерт по consumer lag.

### 6. Безопасность
TLS + SASL/SCRAM + ACL с принципом наименьших привилегий.

## Критерии готовности

- [ ] Вся система поднимается одной командой (`docker compose up` + скрипт).
- [ ] Есть архитектурная диаграмма в `docs/`.
- [ ] Есть тесты: `TopologyTestDriver` для Streams + интеграционные на Testcontainers.
- [ ] В README объяснены выбранные гарантии доставки и обоснованы trade-off.
- [ ] Система переживает остановку одного брокера без потери данных
      (продемонстрировано и задокументировано).
- [ ] Есть runbook: что делать при росте lag, при упавшем коннекторе,
      при `UnderReplicatedPartitions > 0`.
